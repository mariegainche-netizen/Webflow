# Consentio 2026 · correctifs mobile du 26/09/2026

- Site modifié : **Consentio 2026** (`6aaaafd0271107b340148c86`) uniquement.
- Non touchés : « Consentio » (site en ligne) et « consentio-v2-sept2026 » (test).
- Publication : sous-domaine webflow.io uniquement, le 26/09 (le site n'a aucun domaine personnalisé).
- Principe : 100 % natif Webflow (panneau Style, breakpoints), sauf les filtres JS existants et le petit script du bouton « retour en haut ».

## 1. Home › « Integration & technology partners » : texte qui déborde en mobile

- Cause : la ligne `.erp` est en flex et son conteneur `Container 74` prenait la largeur minimale du carrousel (494 px, 926 px avec les clones JS, sur un écran de 390 px). Le texte sortait donc de l'écran.
- Correctif natif : `Container 74` à 100 % de largeur (desktop, hérité partout) et `c2-wrap` + combo `grid` en flex sous 767 px.
- Vérifié à 390 px : plus aucun débordement, le carrousel reste intact.

## 2. Bouton « retour en haut » (mobile)

- Élément : Link Block natif « Bouton retour en haut (mobile) », classes `back-to-top` + combo `is-hidden`, dans le composant **Footer** (donc sur toutes les pages).
- Affichage : uniquement sous 767 px, après un écran de défilement. Rond vert forêt 48 × 48 px, flèche et contour lime, en bas à droite.
- Script : Embed « Script retour en haut », juste après le bouton dans le même composant. Copie commentée : `custom-code/back-to-top-embed.html`.
- Accessibilité : `aria-label` traduit (EN, FR, ES), contour de focus clavier, focus renvoyé sur le logo après activation au clavier, défilement instantané si le visiteur a demandé moins d'animations.
- Pourquoi `is-hidden` est posée dans le Designer : la classe est « utilisée », donc un « Clean up » du Style Manager ne la supprimera pas. Pour voir le bouton dans le Designer (breakpoint mobile), retirer `is-hidden` le temps de l'édition, puis la remettre.
- Test local (Chromium, 390 × 844) : masqué à 0 et 500 px, visible à 900 px, clic → retour à 0 px ; masqué à 768 et 1 280 px ; bien positionné même pendant l'animation d'apparition du footer.

## 3. Footer trop long en mobile

- Correctif 100 % natif (breakpoints tablette et mobile du composant Footer).
- Hauteur à 375 px : 1 140 → 652 px (−43 %).
- Débordements à 600 px : 5 éléments → 0.
- Zones tactiles des liens : 32 px minimum (au-dessus du seuil WCAG 2.2 de 24 px).

## 4. Customer Stories et Resources : grilles non responsive

- Cause : la grille était forcée par du CSS dans le head des pages. `.w-dyn-items.cs-cards-grid` (spécificité 0,2,0) écrasait la media query `.cs-cards-grid` (0,1,0) : 3 colonnes même sur mobile.
- Correctif : grilles natives sur `cs-cards-grid` (et `cs-cards-grid` + `is-resources` pour Resources) : 3 colonnes desktop, 2 tablette, 1 mobile.
- Le CSS de grille est retiré des heads. Anciennes versions : `custom-code/avant-2026-09-26/`. Versions en ligne : `custom-code/customer-stories-head.html` et `custom-code/resources-head.html`.

## 5. 404 au clic en mobile + cartes entièrement cliquables

- Avant : chaque carte avait 2 liens. Seul le petit bouton vert fonctionnait ; le lien de l'image, créé par API, ne menait nulle part. En mobile, la grille à 3 colonnes écrasait la carte et coupait le bouton : un clic sur la carte menait à une 404.
- Correctif : chaque carte est désormais **un seul Link Block natif** relié à « Current Collection Item ». Liens imbriqués et attributs `href` personnalisés supprimés.
- **Correction du 26/09 après-midi.** Les liens « Current Collection Item » posés par l'API ont été publiés sans adresse : plus aucune carte cliquable, en desktop comme en mobile. L'API les lit exactement comme des liens natifs (`{mode: "collectionPage"}`), l'erreur était donc invisible de ce côté. Les 6 cartes ont été rebranchées à la main dans le Designer (Settings › Link › Collection page › élément courant) :

| Page | Élément | Lien |
|---|---|---|
| Resources | `rs-feat` (carte à la une) | Resource courante |
| Resources | `cs-card` (grille) | Resource courante |
| Customer Stories | `cs-card` | Customer Story courante |
| Home | `cs-card` (section Customer Stories) | Customer Story courante |
| Modèle Customer Story | `csl-card` (« More customer stories ») | Customer Story courante |
| Modèle Resource | `cs-card` (articles liés) | Resource courante |

- Règle pour la suite : un lien vers l'élément CMS courant se règle dans le Designer, jamais par l'API.

## 6. Resources : extraits trop longs en mobile

- Correctif natif sous 767 px : hauteur maximale 4,8 em (3 lignes) + contenu masqué au-delà.
- Limite : pas de points de suspension. `line-clamp` n'est pas réglable dans le panneau Style ; il faudrait 1 ligne de CSS personnalisé.

## 7. Ligne méta des cartes : « 1 MIN READ » sur une ligne

- Cause : dans `cs-card-meta` (flex), le bloc « min read » se comprimait comme la date et passait sur 2 lignes (« MIN » / « READ »).
- Correctif natif : classe `cs-card-meta-unit` (`white-space: nowrap`, `flex-shrink: 0`) sur le bloc `data-meta="unit"` des cartes Resources (grille + à la une), Customer Stories, « More customer stories » et articles liés, ainsi que sur l'en-tête du modèle Resource.
- Test local : « min read » tient sur une ligne pour des cartes de 240 à 400 px ; sous 300 px, c'est la date qui passe sur 2 lignes, sans débordement.
